# مرجع طراحی رابط کاربری

**وضعیت:** نیازمند بررسی تصویر واقعی IDM.

## 1. مرجع تصویری
برای تبدیل «مشابه IDM» به نیازمندی دقیق، باید تصویر پنجرهٔ اصلی نسخهٔ نصب‌شده و در صورت امکان پنجرهٔ افزودن لینک یا تنظیمات بررسی شود. اطلاعات شخصی، مسیرها و دانلودهای خصوصی باید در تصویر پوشانده شوند. تا پیش از این بررسی، اندازه‌ها، رنگ‌ها، آیکون‌ها و فاصله‌ها قطعی نیستند.

## 2. ساختار اولیهٔ مورد بررسی
- نوار بالایی با نام برنامه و عملیات اصلی.
- نوار ابزار برای افزودن و کنترل دانلود.
- فهرست مرکزی دانلودها.
- دسته‌بندی یا فیلتر وضعیت، اگر با مرجع هماهنگ باشد.
- ناحیهٔ وضعیت کلی.
- منوی زمینه‌ای برای عملیات مربوط به دانلود انتخاب‌شده.

این‌ها فرض‌های اولیه‌اند و نسخهٔ نهایی با مرجع تصویری تعیین می‌شود.

## 3. ستون‌های احتمالی
- نام فایل
- وضعیت
- اندازه
- پیشرفت
- سرعت
- زمان باقی‌مانده، فقط در صورت تخمین معتبر
- مسیر یا توضیح، در صورت نیاز

ترتیب و نام ستون‌ها پس از مشاهدهٔ مرجع مشخص می‌شود.

## 4. عملیات قابل بررسی
افزودن لینک؛ انتخاب مسیر؛ شروع/مکث/ادامه/لغو؛ تلاش مجدد؛ مشاهدهٔ جزئیات؛ نمایش خطا؛ بازکردن پوشه یا فایل با اقدام صریح کاربر؛ تأیید پیش از حذف داده‌ای که ممکن است لازم باشد.

## 5. اصول بصری و دسترس‌پذیری
- چیدمان مرتب با تراکم مناسب برای فهرست فایل‌ها.
- استفاده از کنترل‌های بومی WinUI 3 در صورت هماهنگی با طرح هدف.
- کنتراست مناسب در تم روشن و تاریک.
- وضعیت فقط با رنگ نشان داده نشود؛ متن یا آیکون هم کمک کند.
- پشتیبانی صفحه‌کلید، فوکوس قابل‌تشخیص و مقیاس‌پذیری DPI.
- اگر فارسی انتخاب شود، RTL باید در نمونهٔ فنی آزمایش شود.
- هویت برنامه مستقل باشد؛ لوگو، آیکون یا دارایی‌های اختصاصی IDM کپی نشوند.

## 6. موارد باز
- نسخهٔ IDM و مقیاس نمایشگر.
- زبان رابط: انگلیسی، فارسی یا هر دو.
- کدام اجزای بصری برای کاربر ضروری‌اند.
- رفتار بستن، کوچک‌سازی و اعلان پایان.
- ستون‌ها، منوها و پنجره‌های ضروری.

خروجی نهایی مرحلهٔ طراحی باید فهرست دقیق اجزا، حالت‌ها، رفتارها و معیارهای پذیرش باشد. این سند قبل از پیاده‌سازی UI تأیید می‌شود.
