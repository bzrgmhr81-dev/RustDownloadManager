# تصمیم‌ها و موارد نیازمند تأیید

این فایل منبع حقیقت پروژه برای تصمیم‌های پذیرفته‌شده، پیشنهادها و موارد باز است. پیشنهاد یک مدل هوش مصنوعی تا وقتی بررسی و تأیید نشده، تصمیم قطعی محسوب نمی‌شود.

## تصمیم‌ها و جهت‌گیری‌های فعلی

| موضوع | وضعیت | توضیح |
|---|---|---|
| کاربرد | تأییدشده بر اساس گفتهٔ مالک | استفادهٔ شخصی و خصوصی؛ فعلاً هدف تجاری یا انتشار عمومی نیست. |
| اولویت رابط | تأییدشده بر اساس گفتهٔ مالک | چیدمان و گردش‌کار IDM تا حد ممکن دقیق حفظ شود؛ زیباسازی نباید ساختار را عوض کند. |
| هویت برنامه | جهت‌گیری فعلی | برنامه نام و هویت مستقل خودش را دارد؛ دارایی‌های اختصاصی IDM کپی نمی‌شوند. |
| مخزن | خصوصی | پروژه فعلاً شخصی است. |
| سیستم‌عامل هدف | پیشنهاد فعلی | Windows 11. |
| سرور اختصاصی | خارج از محدودهٔ فعلی | دانلود مستقیم از میزبان فایل انجام می‌شود. |
| هسته | پیشنهاد بررسی‌نشده | Rust؛ باید با گزینهٔ تماماً C# مقایسه شود. |
| رابط | پیشنهاد فعلی | WinUI 3 + C#؛ باید از نظر سازگاری با چیدمان و RTL آزمایش شود. |
| پایگاه داده | پیشنهاد فعلی | SQLite برای وضعیت محلی. |
| ارتباط UI/Core | باز | مقایسهٔ C ABI/P/Invoke، پردازش جدا با Named Pipe/JSON و تماماً C#. |
| دانلود چندبخشی | مرحلهٔ بعد | پس از پایداری دانلود تک‌اتصالی. |
| افزونهٔ مرورگر | خارج از نسخهٔ نخست | پس از پایدارشدن هسته بررسی شود. |
| شروع کدنویسی | متوقف تا تأیید | ابتدا نیازمندی‌ها، مرجع UI و معماری تأیید شوند. |

## موارد باز برای مالک پروژه

1. تصویرهای مرجع IDM: پنجرهٔ اصلی، افزودن URL و در صورت نیاز منوها یا جزئیات دانلود.
2. زبان رابط نهایی: فارسی، انگلیسی یا هر دو؛ شرح فعلی مرجع فارسی/RTL است.
3. کدام عملیات و پنجره‌های IDM برای استفادهٔ روزمره ضروری‌اند.
4. دلیل ترجیح Rust: یادگیری/علاقه یا الزام فنی؛ این روی انتخاب ساده‌ترین معماری اثر دارد.
5. مقدار زمانی که در هفته می‌توان به پروژه اختصاص داد.
6. نسخهٔ حداقل ویندوز و روش نصب؛ فعلاً Windows 11 فرض شده است.

## قواعد تغییر تصمیم

- هر تغییر مهم باید دلیل، گزینه‌های بررسی‌شده، مزایا و معایب و نتیجه داشته باشد.
- نیازمندی‌های UI بر اساس مرجع واقعی و خواستهٔ مالک تعیین می‌شوند، نه سلیقهٔ مستقل توسعه‌دهنده.
- پیشنهادهای Claude و ChatGPT باید با یکدیگر تطبیق داده شوند؛ در صورت اختلاف، مسئله و شواهد در این فایل ثبت می‌شود.
- هیچ مدل یا ابزار نباید بدون اجازهٔ مالک، کدنویسی اصلی را شروع کند یا تغییر معماری را به‌صورت پنهانی وارد کند.
- چون کاربرد فعلی شخصی است، نیازمندی‌های تجاری مانند سرویس پشتیبانی یا زیرساخت ابری فرض نمی‌شوند؛ امنیت، پایداری و نگهداری همچنان الزامی‌اند.
