# تصمیم‌ها و موارد نیازمند تأیید

این فایل منبع حقیقت تصمیم‌های پروژه است. پیشنهاد یک مدل هوش مصنوعی تا زمان بازبینی و تأیید مالک تصمیم قطعی نیست.

## تصمیم‌ها و جهت‌گیری‌های فعلی

| موضوع | وضعیت | توضیح |
|---|---|---|
| کاربرد برنامه | تأییدشده | استفادهٔ شخصی مالک؛ تجاری‌سازی فعلاً در محدوده نیست. |
| وضعیت مخزن | بررسی‌شده | مخزن GitHub در آخرین بررسی عمومی (Public) است. |
| اولویت رابط | تأییدشده | حفظ چیدمان و گردش‌کار IDM تا حد ممکن دقیق؛ زیباسازی نباید ساختار را خودسرانه تغییر دهد. |
| نسخهٔ مرجع | مبنای فعلی | IDM 6.43 بر اساس تصویر/گزارش موجود؛ در صورت اختلاف با نسخهٔ نصب‌شده، اطلاعات About مرجع نهایی است. |
| جهت پنجره | فرض کاری برای تأیید | چیدمان کلی LTR، درخت سمت چپ و جدول سمت راست؛ متن‌های فارسی داخل کنترل‌ها راست‌چین. کل پنجره نباید آینه شود. |

| ارتباط Rust/UI | باز، فقط در صورت انتخاب Rust | C ABI/P/Invoke در برابر پردازش جدا با Named Pipe/JSON. |
| ذخیره‌سازی | پیشنهاد فعلی | SQLite برای وضعیت محلی، پس از تصمیم دربارهٔ مالکیت موتور. |
| سرور اختصاصی | خارج از محدوده | دانلود مستقیم از میزبان فایل؛ حساب ابری لازم نیست. |
| شروع کدنویسی اصلی | متوقف تا تأیید | پیش از آن باید مرجع UI، معماری و معیارهای پذیرش روشن شوند. |

## اصلاحات مستندشده از بازبینی رابط

1. عبارت «رابط RTL» برای جهت کلی پنجره دقیق نیست؛ فرض فعلی LTR layout + متن فارسی راست‌چین است.
2. درخت گروه‌ها باید ریشهٔ «همهٔ دانلودها» و گروه «پروژه‌های گربر (Grabber)» را هم پوشش دهد، علاوه بر فایل‌های فشرده، اسناد، موسیقی، برنامه‌ها، تصویری، ناتمام، تکمیل‌شده و صف‌ها.
3. جدول طبق گزارش تصویر شامل ۹ جزء/ستون است: نام فایل، «ص»، سایز، ستون باریک آیکونی، وضعیت، زمان باقیمانده، سرعت، آخرین تلاش، توضیحات. معنای دو مورد کوچک هنوز روشن نیست و نباید حذف یا حدس زده شود.
4. منوها و دکمه‌های نوار ابزار باید به‌صورت کامل فهرست شوند؛ در حال حاضر فقط ترتیب گزارش‌شدهٔ منوها و حضور دکمهٔ «آدرس» ثبت شده است.
5. برای قابلیت‌های هنوز پیاده‌نشده، پیشنهاد اولیه حفظ موقعیت و نمایش غیرفعال است؛ تصمیم نهایی برای هر مورد نیازمند بررسی مالک است.
6. معیار پذیرش ظاهر به تلورانس عددی نیاز دارد؛ اعداد دقیق پس از ثبت تصویر اصلی، اندازهٔ پنجره و DPI تعیین شوند.

## موارد باز برای مالک پروژه

1. تأیید نهایی اینکه تصویر نسخهٔ نصب‌شده نیز LTR با متن فارسی راست‌چین است.
2. انتخاب سیاست دکمه‌ها/گروه‌های قابلیت‌های پیاده‌نشده: غیرفعال، «به‌زودی» یا حذف. پیشنهاد فعلی: غیرفعال، با حفظ موقعیت.
3. دلیل ترجیح Rust: یادگیری/علاقه یا الزام فنی.
4. انتخاب WinUI 3 یا WPF پس از نمونهٔ مقایسه‌ای.
5. تأیید تلورانس‌های عددی ظاهر پس از ثبت اندازه و DPI مرجع.
6. تعیین اینکه در نسخهٔ اول کدام پنجره‌های جانبی علاوه بر پنجرهٔ اصلی و مسیر Add URL باید بازسازی شوند.
7. تعیین مقدار زمان هفتگی و نسخهٔ حداقل ویندوز؛ پیش‌فرض فعلی Windows 11 است.

## قواعد تغییر تصمیم

- هر تغییر مهم باید با دلیل، گزینه‌های بررسی‌شده، مزایا/معایب و نتیجه ثبت شود.
- تفاوت عمدی با مرجع UI باید ثبت و توسط مالک تأیید شود.
- ChatGPT و Claude باید همین فایل‌ها را به‌عنوان منبع حقیقت مشترک در نظر بگیرند؛ مدل‌ها نباید بر اساس فرض‌های متناقض کار کنند.
- هرگز رمز، token، کوکی، URL خصوصی یا log واقعی را به مخزن عمومی اضافه نکنید.
- عمومی بودن مخزن با شخصی بودن هدف برنامه تناقض ندارد؛ این دو ویژگی باید در مستندات جدا ثبت شوند.
